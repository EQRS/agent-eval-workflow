## 一、为什么是这道题

M-1 到 M-3 的材料量分别是 15 万、6.9 万、4.2 万 token。

**M-4 直接上 58.4 万**——是 M-1 的 3.9 倍，**远超单 agent 的上下文预算**。

| 题 | 材料量 | 相对 M-1 |
|---|---|---|
| M-1 | 15 万 | 1× |
| M-2 | 6.9 万 | 0.46× |
| M-3 | 4.2 万 | 0.28× |
| **M-4** | **58.4 万** | **3.9×** |

**这是第一次真正「装不下」的题。**

## 三、题目

### 3.1 任务描述

```
架构地图：为 src/ 下的全部 327 个 TypeScript 文件绘制一份架构地图。

需要产出：
① 分层结构：哪些是 UI 层、哪些是服务层、哪些是平台层
② 模块依赖图：src/server/modules 下 22 个模块之间谁依赖谁
③ 关键路径：从「一个 HTTP 请求」到「数据库写入」经过哪些层
④ 循环依赖：有没有模块互相依赖

对每条依赖，给出：
- 依赖方 → 被依赖方
- 证据（哪个文件的哪一行 import）
```

### 3.2 为什么这道题单干做不完

| 因素 | 数字 |
|---|---|
| 文件数 | 327 个 |
| 总 token | 58.4 万 |
| 单 agent 上下文 | 约 20-100 万（取决于模型） |
| **要读完全部文件** | **装不下或读不完** |

**即使上下文够，327 个文件逐个读也要很多步**。

### 5.2 关键事实

| 项 | 数值 |
|---|---|
| 模块总数 | 22 |

| settings | 3 | imports, media, roles |

| content | 2 | interactions, search |

**这几个是「基础模块」——改它们影响面最大。**

## 七、M-4 的教训（补充到设计文档）

### 7.1 设计失误：「材料量大」不等于「需要协作」

**设计假设**：58 万 token 装不下 → 单干必然抽样 → 会漏。

**实际结果**：S 组**没有抽样**，改用**机械提取**做到了 100% 覆盖。

| 假设 | 实际 |
|---|---|
| 装不下 → 必须抽样 | ❌ **S 组用 AST 正则提取，全覆盖** |
| 覆盖不了 → 会漏 | ❌ **28 条边全对** |

**关键区分**：

| 任务类型 | 单干能做完吗 | 协作有价值吗 |
|---|---|---|
| **可机械提取**（import 关系、文件计数） | ✅ 能 | ❌ 无价值 |
| **需逐个理解**（代码审查、文档一致性） | ❌ 不能 | ✅ 有价值 |

**M-4 属于前者**——虽然材料多，但结构可以机械提取。

### 7.2 修正后的题目筛选标准

**出题前先问一句**：

> **这个任务能不能用脚本机械完成？**
>
> 如果能 → **不要出这道题**，单干也能做，测不出协作价值。
> 如果不能 → 才有出题价值。

**具体判据**：

| 可以机械做 | 需要人工判断 |
|---|---|
| 提取 import 关系 | **判断某段代码写得对不对** |
| 统计文件数、行数 | **判断测试是不是假测试** |
| 提取表结构 | **判断某处改动会破坏什么** |
| 比对两个清单的差集 | **判断文档描述是否属实** |

### 7.3 M-4 仍然有价值的发现

虽然 T 组优势不强，但它发现了 S 组没提的两件事：

| 发现 | 价值 |
|---|---|
| **页面与 API 是两条独立通路**（37/49 页面直连服务层） | 解释了 M-1 的「路由层不写 guard」现象 |
| **19 处裸 fetch 导致错误码退化** | 真实的代码质量问题 |

**这两个都不是「机械提取」能发现的**——需要理解代码意图。

### 7.4 累计的五次误判

| # | 谁 | 误判 | 原因 |
|---|---|---|---|
| 1 | 我 | M-3 的 0007/0021「无数据拷贝」 | 正则窗口太窄 |
| 2 | 我 | M-4 的 28 条边「多一条」 | **漏了动态 import** |
| 3 | S 组 | M-3 的「OFF 在 BEGIN 之后」 | 注释里的 BEGIN 干扰 |
| 4 | T-agent3 | M-3 的 31 条「引用了未创建的表」 | 同文件自引用 |
| 5 | agent2 | D1 的「可能已在积累脏数据」 | 无证据的推断 |

**共同原因**：

> **用关键词/正则判语义，而语义的结构比正则复杂。**
>
> **解法：涉及「X 是否存在」的判断，必须用多种方法交叉验证。**

- 不要求分析运行时性能
