# 测评方案 · 官方 Agent Teams

> 被测：DSH 内建官方 Agent Teams
> 对象：atb/tasks/ 题库（80 题）
> 日期：2026-11-17

---

## 一、测什么（三个层次）

| 层次 | 回答的问题 | 手段 |
|---|---|---|
| **可用性** | 功能能不能正常工作 | 团队创建/派发/汇总全流程，有硬断言 |
| **好用程度** | 相比单 agent 是否真更好 | **S 组 vs T 组对照实验** |
| **协作质量** | 团队是否真的互补 | 分析各组发现的差异分布 |

**为什么要有基线组**：只测团队本身，回答不了「组队值不值」。

---

## 二、三组对照

| 组 | 配置 | 说明 |
|---|---|---|
| **S 组** | **1 个 subagent** | 单 agent 基线 |
| **T 组** | **Lead + 3 teammates** | 官方 Agent Teams，3 个专业身份 |
| **T-单专业组**（可选） | Lead + 3 个**同专业** | 验证「专业分工」是不是关键 |

### 2.1 T 组的 3 个专业身份

沿用已验证的有效组合（前 48 题实测）：

| 身份 | 关注点 |
|---|---|
| **安全工程师** | 鉴权/越权/敏感数据/对抗性 |
| **性能工程师** | 查询成本/锁/内存/实测 |
| **SRE（运维）** | 部署/回滚/可观测/容量 |

---

## 三、选题策略

### 3.1 从 80 题中选（按四类考点配比）

| 类型 | 题数 | 代表题 | 为什么选 |
|---|---|---|---|
| **② 方案缺陷** | 6 | N-24, N-27, N-31, N-46, N-59, N-69 | 区分度最高 |
| **③ 无用功** | 2 | N-29, N-52 | 测「先读现状」能力 |
| **④ 倒退** | 1 | N-30 | 需实测反驳 |
| **L4 系统性** | 3 | N-46, N-61, N-71 | 需跨模块理解 |
| **合计** | **12 题** | | |

### 3.2 为什么是 12 题

| 考虑 | 说明 |
|---|---|
| 覆盖 | 4 类考点 × 3 组 = 足够统计 |
| 成本 | 12 题 × 4 agent = 48 个 agent |
| 时间 | 预计 40-60 分钟 |

## 五、要测的团队能力（硬断言）

| # | 能力 | 断言 |
|---|---|---|
| 1 | **并行派发** | 3 个 teammate 同时工作，互不阻塞 |
| 2 | **专业分工** | 各组发现的维度不重叠 |
| 3 | **共享文件系统** | teammate 能读到同目录文件 |
| 4 | **Lead 汇总** | Lead 能整合 3 份报告且不丢关键信息 |
| 5 | **任务板** | team_task_* 能创建/认领/完成 |
| 6 | **中断恢复** | interrupt_agent 后能继续 |
