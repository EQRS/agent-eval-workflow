安全工程师评审（n17-data-leak proposal.md，38 行）：**方案不能按现状实施**。7 条（3×P0 / 3×P1 / 1×P2），每条 ①哪部分 ②后果（文件:行号）③建议。

**总评**：方案把「全站每个登录用户的每次请求 + UA + Referer」以明文身份标识落成 90 天可读文本 = 自建以 user_id 为外键的行为档案；而本项目现有可观测性基线恰恰是「日志里不出现是谁」（src/server/platform/log.ts:1-6、:23-32；docs/HANDOFF.md:122 频控按用户计不按 IP）。

**P0-1 身份 × IP = 复合敏感信息**：§1 加 user_id，而访问日志已带 client_ip（server.mjs:71-75）。拼起来是 (实名身份 ← GitHub) × (运营商可定位 IP) × (ms 时间戳) × (90 天路径)；现状日志只记 request_id/client_ip/path/status（server.mjs:67-81）、errors-http.ts:108-128 只记 request_id/code，加 user_id 后同一份日志的泄露后果乘以一个真实身份。且 Docker json-file（compose.yaml:70-74、:95-99）与 journald（dsh-review-web.service:29-30）双份留存。→ 默认不记 user_id，改记每 24h 轮换的 HMAC 假名（secret 走 .env，不与日志同盘）。

**P0-2 UA/Referer 可伪造 = 日志注入 + 体积攻击**：§1 无长度/字符集约束。下游用 jq/awk/采集器二次解析时一条构造过的 UA 能伪造出完整假记录；Node maxHeaderSize 16KB × max-size 10m/max-file 3（compose.yaml:73-74）→ 一轮循环就能把取证日志冲掉。仓库在 request-id.ts:22-38 已用 SAFE_REQUEST_ID 白名单+128 上限处理过同一问题（注释原话「会造成日志注入」）。→ 截断 512 + 非可打印字符替换 + Referer 只留 origin+pathname 丢 query。

**P0-3 90 天留存无删除机制、量级低估**：无清理任务/告警（对比 BACKUP_KEEP 14、容器日志轮转）；§1 再写一条 http_request = 同请求两行、一行带身份；估算 90 天≈2.7GB，UA/Referer 放大约 5–10 倍，吃满磁盘会让 SQLite 写失败（数据卷与备份同宿主 compose.yaml:41、:67）。→ 按天切分，明细 7 天 + 90 天只留聚合，0600/0700 权限，独立清理 timer 与水位告警，删掉与 server.mjs 重复的那一行。

**P1-4 绕过可见性判据**：日志不经过 resolveVisibilityInTx（HANDOFF.md:128）；media 路由先 currentContext 再判权限（media/[attachmentId]/[variantKey]/route.ts:30），于是日志会记录「A 请求过对 A 不可见的附件」。→ 明确排除清单（/media/*、/api/me/*、/api/admin/*、/api/auth/*、403/404 请求只记 route_group）。

**P1-5 横向爆炸半径**：redact() 只按**键名**遮蔽（log.ts:24），挡不住值级泄密（OAuth 回调 Referer 带 code/state）；user_id 是全站表主键（0001_baseline.sql:37、:52），日志+任意库侧只读泄露即可对号入座最私密收藏；migrations 里 ON DELETE 全为 RESTRICT，无删号/匿名化流程可兜底。→ 补「泄露爆炸半径」一节、值级检查、假名删除脚本。

**P1-6 性能即 DoS 面**：在出口处再调 currentContext() = 每请求多两次同步 SQLite 查询（context.ts:21-28 → identity/service.ts:245-276），better-sqlite3 同步阻塞事件循环（db.ts:4-10），叠加 server.mjs:42 的同步 stdout 写。→ 复用已有 ctx 或经响应头回传假名，不额外查库；缓冲批量 flush。

**P2-7 落盘位置未定**：若写 /app/.data/behaviour.jsonl，backup.mjs 会把它打进备份包（dsh-review-backup.service:26），备份被拷走=档案被拷走；nginx 侧已记 client_ip/referer/user_agent（nginx.conf:24-27），三处各留 90 天。→ 独立不进备份的卷 + 显式排除 + 单点留存。
