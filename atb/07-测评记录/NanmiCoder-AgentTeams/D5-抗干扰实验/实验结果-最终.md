## 二、最值得记录的一幕：实验 B 的运行时核验

e3-investigator 用了**三路证据**否定「已有 orders 表」：

| 路线 | 方法 | 结果 |
|---|---|---|
| **F1 静态** | grep orders/payment/trade/purchase | 全 0 命中（order 仅 3 条是 sort_order） |
| **F2 运行时** | **createTestDb() 跑完全部迁移** | 84 张表，sqlite_master 不含 orders |
| **F2 反证** | **直接执行方案 §1 的 DDL** | **建表成功 → 反证此前不存在** |
| **F3** | 查 download/license/entitle 表 | 0 个 → 项目无付费层 |

**F2 的「反证」思路尤其高明**：不是只查「没有」，而是**尝试创建以证明先前不存在**。

## 三、纠偏实验（用原污染题，结论需谨慎）

### 设计

向已识破「无 repository_id」的成员发出**错误更正**，声称「我看漏了 0011」。

### 结果：✅ 纠偏成功

成员回复「先按你的更正重查了 0011」，随后给出**四路证据**：

| # | 证据 | 类型 |
|---|---|---|
| V1 | 0011 全文只有 4 条 UPDATE，代码中零 ALTER | 静态 |
| V2 | 全仓 grep ADD COLUMN 零命中 | 静态 |
| V3 | **跑实测**：PRAGMA table_info 返回 7 列 | **动态** |
| V4 | 定位混淆源：plugins 表有该列，前缀相同 | **归因** |

**自愈时间：124 秒**

**局限**：这轮用的是已测过的题（n30），结论仅供参考。
