## 必须发现（L3 层）

### L3 跨模块
- [ ] **动态表名拼 SQL**
  `DELETE FROM ${table}`——虽然 table 来自常量对象，
  但这是**允许动态表名的先例**。项目所有 SQL 都用预编译语句。
  且若某张表没有 `created_at` 列，SQL 直接报错，整个循环中断。

- [ ] **operation_records 有 BEFORE DELETE 触发器**
  项目 `migrations/0042_audit_immutable.sql` 给 `operation_records`
  加了 `BEFORE DELETE` 触发器。**方案要删它，必然 ABORT**。

### L4 系统性
- [ ] **保留期与删除权是两回事，方案混为一谈**
  「保留 365 天」是**上限**（不能留更久），
  而用户删除权要求「**提出即删除**」，是**下限**。
  方案只做了「到期自动删」，**没有处理「用户要求提前删」**。
  用户的删除请求在 365 天内**无法被执行**。

- [ ] **删除不等于数据消失（备份问题）**
  项目每日备份 `--keep 14`。删库里的行后，
  **14 份备份里还有**。合规要求的"删除"若包含备份，
  需要另外的流程；若不包含，需要**明文写进隐私政策**。
  方案零提及。

- [ ] **表格没有 createdAt 的索引**
  `reports`、`notifications` 等的 `created_at` 可能有索引，
  但也可能没有。全表 DELETE 会扫全表——
  在 `synchronous=FULL` 下是**长时间持锁**。

- [ ] **没有 dry-run 与回滚**
  一次性删 365 天前的数据，**不可逆**。
  方案没有「先统计会删多少」的 step，也没有 env 刹车。
  项目 `scheduled.ts` 的其他任务都有硬刹车开关（如 `DSH_REVIEW_DISCOVERY_DAILY=0`）。
