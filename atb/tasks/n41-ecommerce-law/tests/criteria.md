## 必须发现（每项 1 分）

### 域外知识（电子商务法）
- [ ] **O-1 平台不能靠一句免责声明推卸责任**
  《电子商务法》第 38 条：平台知道或应当知道平台内经营者销售的商品不符合
  保障人身、财产安全的要求，或者有其他侵害消费者合法权益行为，**未采取必要措施的，
  依法与该平台内经营者承担连带责任**。
  §3 的「平台仅提供技术服务」**不能免除法定连带责任**。

- [ ] **O-2 身份证号是敏感个人信息，存明文违法**
  §1 的 `id_number TEXT NOT NULL` 存明文身份证号——属 PIPL 第 28 条敏感个人信息，
  需**单独同意 + 单独存储 + 加密**。方案的 SQL 里是三无（无加密、无单独同意、无保留期）。

- [ ] **O-3 未处理「平台内经营者」的信息公示义务**
  《电子商务法》第 15 条：平台应当**公示平台内经营者的经营主体信息**
  （名称、统一社会信用代码等）。方案只存了内部核验，**没有对外公示字段**。

- [ ] **O-4 没有消费者权益保障义务**
  《电子商务法》第 58 条：消费者权益争议，平台应提供**经营者真实名称、地址和有效联系方式**，
  以及**先行赔付**机制。方案零提及。

### 对抗性
- [ ] **S-1 身份证号明文可被内部人员导出**
  `merchant_info` 与其他业务表在同一个 SQLite 文件里，
  而每日备份是**明文**（`scripts/backup.mjs`）。备份一旦外泄，
  等于全量身份证号泄露。

- [ ] **S-2 没有唯一约束，同一身份证可注册多个账号**
  §1 的 `id_number` 没有 `UNIQUE` 约束。
  一个身份可对应 N 个 `user_id`，无法防止「同一人开多号刷单」。

### 跨系统
- [ ] **C-1 users 被 76 处外键引用，新表外键缺策略**
  §1 的 `REFERENCES users(id)` 没写 `ON UPDATE/DELETE`。
  全库统一是 `ON UPDATE RESTRICT ON DELETE RESTRICT`（`0001_baseline.sql`）。
