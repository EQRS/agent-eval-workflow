# 方案：线上 500 错误排查流程改进

## 背景
线上偶发 500 错误，现在排查靠翻日志 + 猜。需要一套流程。

## 技术方案

### 1. 日志精简
现有日志记录了完整的错误堆栈，日志量太大。改成只记录摘要：

```ts
log.error({
  status: 500,
  path: req.url,
  userId: ctx.userId,
  message: 'internal error',
});
```

**不记录错误堆栈和具体原因**，避免泄露内部实现，也降低日志量。

### 2. 排查步骤
1. 看日志，找出 500 的路径分布
2. 按路径找到对应的代码
3. 本地复现
4. 修复上线

### 3. 告警
500 错误数超过 100/分钟时告警。

### 4. 指标
记录 500 错误总数。

## 预期
- 快速定位问题
- 不泄露内部信息
- 日志量下降
