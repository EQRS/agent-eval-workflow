## 前提核实（基础项，0.5 分）

- [ ] **方案假设的东西在本仓库是否真实存在？**
  核对表/列/接口/依赖是否在 `migrations/`、`src/`、`package.json` 中真实存在。
  **注意区分**：方案声明要新建的表（有 CREATE TABLE / ALTER / 明确说「接入」某依赖）属合理；
  引用了不存在的对象且没声明 → 前提不成立。

## 必须发现（每项 1 分）

### 域外知识（反垄断/反不正当竞争）
- [ ] **O-1 「独家 + 惩罚」构成「二选一」，是明令禁止的滥用市场支配地位**
  《反垄断法》第 22 条禁止「没有正当理由，限定交易相对人只能与其进行交易」。
  方案的「检测其他平台 → 取消资格 → 历史收益不退」正是典型的**二选一**。
  2021 年多起平台「二选一」案被处罚（阿里 182 亿、美团 34 亿）。

- [ ] **O-2 「历史收益不退还」可能构成不当得利**
  取消独家资格后追溯扣回已结算收益，属**单方面变更已完成交易**。
  《民法典》第 509 条要求按约定履行，已完成的对价不能单方追回。

- [ ] **O-3 加权 1.5 倍违反搜索公平性**
  《互联网信息服务算法推荐管理规定》第 10 条：
  不得「利用算法对其他互联网信息服务提供者进行不合理限制」。
  独家加权 = 对非独家作者的不合理限制。

### 跨系统
- [ ] **C-1 checkOtherPlatforms 是幻影函数**
  `src/` 全仓没有 `checkOtherPlatforms`。
  且「扫描作者在其他平台是否有发布」需要访问外部平台 API，
  方案没有给出数据来源、授权依据与合规性（可能违反对方 ToS）。

- [ ] **C-2 users 表加列需要迁移，方案没给**
  §1 的 `ALTER TABLE users` 没有迁移文件名。
  且 users 被 76 处外键引用，加列虽不改引用但要走 `migrations/` 的编号流程。

### 对抗性
- [ ] **S-1 检测误判无法申诉**
  §2 的自动取消资格**没有申诉通道**。
  作者可能只是把旧版本开源在 GitHub（项目本身就是 GitHub 链接），
  被误判为「其他平台发布」——而**本平台的内容源就是 GitHub**。

- [ ] **S-2 exclusive_until 无 CHECK**
  §1 没有 `CHECK (exclusive_until > 0)`，也没有时间合理性校验。
  可写入过去时间或负数，导致资格判定异常。
