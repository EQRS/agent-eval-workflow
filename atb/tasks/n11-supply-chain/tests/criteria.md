## 必须发现（每项 1 分）

### 对抗性思维
- [ ] **S-1 自动合并 patch = 供应链攻击入口**
  §2「patch 版本自动合并」——
  **patch 版本的恶意更新是真实存在的攻击手法**（如 event-stream、ua-parser-js 事件）。
  攻击者拿到包的发布权限后，可以发一个 patch 版本植入后门。
  **自动合并等于把「是否信任这次更新」的判断交给了攻击者。**
  正确做法：所有版本变更都要人工审核，或至少对敏感包（有 postinstall 脚本）强制审核。

- [ ] **S-2 自动部署放大攻击面**
  §3「合并后自动触发 CI/CD 并部署」——
  即使测试通过，测试也无法发现后门（后门通常只在生产环境激活）。

### 域外知识
- [ ] **O-1 semver 不是安全边界**
  semver 只约定 API 兼容性，**不约束代码安全性**。
  patch 版本可以包含任何代码变更，包括恶意代码。
  「patch 是小改动」是错误认知。

- [ ] **O-2 lockfile 与 semver 的语义差异**
  §4「保持 package-lock.json 同步更新」——
  **lockfile 锁定的是确切版本，但它本身也是依赖**。
  若 lockfile 被自动更新，等于绕过了 semver 约束（可以跳到任意版本）。

### 跨系统交互
- [ ] **C-1 升级后 build 环境差异**
  本地开发、CI、生产可能有不同的 Node 版本、操作系统。
  一个新包可能在某环境构建失败或行为不同。
