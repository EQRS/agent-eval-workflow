## 必须发现（每项 1 分）

### 跨系统（真实约束）
- [ ] **C-1 withTransaction 的回调必须是同步函数，方案用了 async**
  项目 `src/server/platform/tx.ts:37-52` 明确要求「传入的回调必须是同步函数」，
  因为 better-sqlite3 是同步驱动。方案的 `async (tx) => {...}` **无法套进现有事务**，
  要么编译不过，要么被拆成多个自动提交。

- [ ] **C-2 发通知不该在事务内，它有外部副作用**
  §2 把 `notifications.send` 放进事务——
  若通知是真的发邮件/推送，**外部调用无法回滚**：
  事务回滚后通知已发出，用户收到「你的评测已发布」但实际没发布。
  且外部调用慢会长时间持有写锁。

### 性能
- [ ] **P-1 事务内做外部 I/O 会把写锁持有时间拉长到秒级**
  SQLite 单写者，事务期间**全站零写入**。
  better-sqlite3 同步驱动 + busy_timeout 5000ms，
  一个慢通知就能让全站写请求排队到超时。

- [ ] **P-2 incrementCount 可能是热点行，加剧锁竞争**
  同一插件的所有评测发布都更新同一行统计，
  该行成为写热点。方案没考虑用异步聚合替代实时更新。

### 跨系统
- [ ] **C-3 项目已有事务纪律，方案没遵守**
  `tx.ts:14-19` 定义了「受限事务上下文」，禁止事务外继续使用。
  且 `db.ts:6-8` 明确「业务事务保持短小」。
  方案把三件事塞进一个事务，与这两条纪律冲突。
