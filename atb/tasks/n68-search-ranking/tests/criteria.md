## 必须发现（L3 层）

### L3 跨模块
- [ ] **bm25 的权重参数是建表时指定的，不是 INSERT**
  FTS5 的 `bm25(table, w1, w2, ...)` 权重是**函数参数**，
  不是表里的数据。§2 的 `INSERT INTO review_search (review_search, rank)`
  **语法完全错误**。

- [ ] **项目已有 BM25_WEIGHTS 常量**
  `src/server/modules/search/index.ts` 有 `BM25_WEIGHTS` 定义，
  且注释说明权重顺序**依赖列定义顺序**。
  方案没有引用。

- [ ] **bm25() 返回负数，越大越不相关**
  FTS5 的 `bm25()` 返回**负值**（越小越相关）。
  §1 的 `bm25(...) * -1 AS score` 再 `ORDER BY score DESC`
  是**对的**（取负后降序 = 原来升序）。
  但若有人误以为 bm25 返回正数并去掉负号，排序会反。

### L4 系统性
- [ ] **改权重会影响所有搜索场景**
  `review_search` 同时服务：
  - 评测全文搜索
  - 插件名匹配（`plugin_name` 列）
  - 目录页关键词（另一条路径）
  改权重会影响**所有**这些场景，方案没有分别评估。

- [ ] **trigram 分词下 bm25 的意义不同**
  `0014_review_search.sql` 用 `tokenize = 'trigram'`。
  trigram 把文本切成 3 字符片段——**中文的"词"不存在**。
  bm25 在 trigram 上的相关性**与英文词频模型不同**，
  方案的"标题权重 10"未必有效。

- [ ] **1-2 字查询走 LIKE 回退，不走 bm25**
  项目 `search/index.ts` 对 1-2 字查询用 `LIKE` 回退。
  这种情况下**没有 bm25 排序**，方案只优化了 bm25 路径。

- [ ] **没有基线，改完无法验证**
  §预期"搜索更准"不可度量。
  项目有 `server.mjs` 的 duration_ms 日志，但没有相关性指标。
