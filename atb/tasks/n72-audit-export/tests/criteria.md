## 必须发现（L3 层）

### L3 跨模块

- [ ] **operation_records 不可变，但导出会复制它**
  项目 0042 给 operation_records 加了 BEFORE DELETE/UPDATE 触发器。
  导出是读操作，不受影响——但方案说「归档发到对象存储」，
  **归档件是普通文件，可以被任意修改**，失去了不可变性。

- [ ] **SELECT * 会带出 target_snapshot/changes**
  这两列是 JSON，可能含**用户内容与个人信息**。
  导出到对象存储 = **PII 外泄**（且对象存储可能无访问控制）。

### L4 系统性

- [ ] **导出是 GET，会被缓存与记录**
  GET 请求会被 nginx 与浏览器缓存。
  审计日志含敏感信息，缓存后**任何人拿到 URL 即可访问**。

- [ ] **没有分页与上限，会一次读出全表**
  operation_records 是**只增不减**的表（不可删）。
  一次 SELECT * 会把整表读进内存（OOM 风险）+ 在同步驱动下阻塞事件循环（db.ts:8）。
  **注意**：WAL 下读不阻塞写（db.ts:53），不要用「持读锁」作为论据。

- [ ] **没有审计导出行为本身**
  「谁导出了审计日志」是最该审计的事件。方案没有记录。

- [ ] **对象存储的凭证没有管理方案**
  项目 .env.example 有 SESSION_SECRET 等，但没有对象存储凭证。
  方案没有说明凭证如何注入、如何轮换。

- [ ] **合规要求的是「不可篡改的留存」，不是「导出一份 JSON」**
  导出到普通对象存储满足「留存」但不满足「不可篡改」。
  需要 WORM 存储或哈希链——方案只做了「导出」。
