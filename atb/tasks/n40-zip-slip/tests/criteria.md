## 前提核实（基础项，0.5 分）

- [ ] **方案假设的东西在本仓库是否真实存在？**

## 必须发现（每项 1 分）

### 对抗性（Zip Slip）
- [ ] **S-1 extractAllTo 存在路径穿越漏洞**
  这是 **Zip Slip** 的经典写法：恶意 zip 里的文件名可以是
  `../../../etc/passwd` 或绝对路径，解压时**写到目标目录之外**。
  `AdmZip.extractAllTo` 在部分版本需要显式开启路径校验。

- [ ] **S-2 没有体积上限，zip 炸弹可打满磁盘**
  `req.arrayBuffer()` 把整个文件读进内存——**没有大小限制**。
  且「压缩比炸弹」（如 42.zip）解压后可达 PB 级。
  项目 nginx 有 `client_max_body_size 12m` 但方案没提解压后的上限。

- [ ] **S-3 解压目录可被并发覆盖**
  `extractDir` 没有说明如何生成。若按包名/用户名拼接，**同名包会互相覆盖**；
  若可预测，攻击者可预先占用路径。

### 跨系统
- [ ] **C-1 项目已有 FileStore 落盘纪律，方案绕开了**
  `src/server/platform/file-store.ts` 有明确四条：
  服务端生成 storage_key、路径穿越防护、临时文件 + rename、**写后回读校验**。
  方案直接用 `AdmZip` 解压到目录，**完全绕开这套**。

- [ ] **C-2 项目没有 AdmZip 依赖**
  `package.json` 里没有 `adm-zip`。方案引入新依赖，
  需要考虑供应链风险（且项目已有 n11 题专门讨论依赖审查）。

- [ ] **C-3 附件已有独立表与存储，方案重复建设**
  `migrations/0003_auth_media.sql` 有 `attachments` + `attachment_blobs` 表，
  文件存 `DSH_REVIEW_MEDIA_ROOT`。方案解压后的文件**没有落表**，
  下次请求也找不到。

### 域外知识
- [ ] **O-1 用户上传的 zip 可能含他人受版权保护的内容**
  方案「自动解压分析」，但没有内容来源校验。
  若用户打包了他人插件，平台成了**侵权内容的存储与分发者**。
