## 必须发现（L3 层，每项 1 分）

### L3 跨模块
- [ ] **附件的真实引用关系不是 content_attachments**
  `migrations/0003_auth_media.sql` 里没有 `content_attachments` 表。
  附件是通过 `attachment_blobs.file_id` 关联到 `attachment_files`，
  而"内容引用了哪个附件"需要查 `content_entities` 的正文 Markdown 里的图片引用。
  **方案假设的关联表不存在。**

- [ ] **删 attachments 行会被 RESTRICT 挡住**
  `attachment_blobs.file_id REFERENCES attachment_files(id) ON DELETE RESTRICT`。
  顺序错了会报外键失败。

### L4 系统性
- [ ] **「没有引用」的判断漏掉了「已撤回」这个状态**
  项目的内容有 `withdrawn_at` / `hidden_at`（`content_entities`）。
  **已撤回的内容不是"删除"，它的附件仍在引用中**。
  若清理逻辑只看"是否被引用"，撤回的内容附件会**保留**；
  但若有人按"内容不可见 → 附件无引用"来判断，就会**误删仍属用户的数据**。

- [ ] **物理文件删除不可逆，与备份策略冲突**
  `store.remove()` 是物理删除。但项目每日备份（`--keep 14`）里
  仍保留 14 天的旧文件。**库删了但备份里还在**——
  从合规角度，用户的删除权**没有被真正执行**（备份里有）。
