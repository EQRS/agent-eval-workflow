## 前提核实（基础项，0.5 分）

- [ ] **方案假设的东西在本仓库是否真实存在？**
  核对表/列/接口/依赖是否在 `migrations/`、`src/`、`package.json` 中真实存在。
  **注意区分**：方案声明要新建的表（有 CREATE TABLE / ALTER / 明确说「接入」某依赖）属合理；
  引用了不存在的对象且没声明 → 前提不成立。

## 必须发现（每项 1 分）

### 域外知识（PIPL）
- [ ] **S-1 user_id + IP + UA 组合是可识别个人信息，进日志需单独告知与授权**
  §1 同时记 user_id、client_ip、user_agent、referer 四项。
  **PIPL 第 13 条要求处理个人信息须取得同意，第 17 条要求告知处理目的与方式。**
  方案把「行为分析」这个新目的直接套在现有日志上，**没有告知、没有授权**。
  现有 log.ts:1-6 明令「不记录凭据、会话 token、私有正文」——userId 虽不在黑名单，但它是稳定标识。

- [ ] **S-2 保留 90 天缺少最短必要期限论证**
  §3「保留 90 天」——PIPL 第 19 条要求「保存期限应当为实现处理目的所必要的最短时间」。
  方案直接写 90 天，没有说明为什么是 90 天、行为分析需要多久。

- [ ] **O-1 用户删除权无法覆盖日志**
  现有注销流程只删库里的行，**日志文件里的 user_id 不会被删**。
  PIPL 第 47 条要求删除权覆盖所有副本。方案没给日志侧的删除能力。

### 对抗性
- [ ] **C-1 referer 可被伪造，且可能含第三方敏感信息**
  §1 记 referer——攻击者可构造含敏感参数的 referer 污染日志；
  且从外部站跳转来时，referer 可能带对方站点的 URL 参数。

- [ ] **C-2 client_ip 在反代后的真实性与信任边界**
  项目用 nginx 反代（docker/nginx/）。req.ip 若直接取 X-Forwarded-For，
  **攻击者可伪造任意 IP**。需核实项目是否有 client-ip 解析模块及其信任配置。
